# ChitSmart — Build Variants

This document describes every supported build configuration across the three application
layers (Android app, admin dashboard, backend API) for four environments: local
development, local Docker, staging, and production (cloud).

---

## Environment overview

| Environment | Purpose | Who uses it |
|---|---|---|
| **Local dev** | Fast iteration — hot reload, no Docker for app code | Individual developers |
| **Local Docker** | Full stack in containers — mirrors production networking | Integration testing, QA |
| **Staging** | Cloud-hosted pre-production — real infrastructure, test data | QA, stakeholder review |
| **Production** | Live customer traffic | Operations |

## Android app

### Debug (local development)

Build command:

```powershell
.\gradlew assembleDebug
```

Key properties:

| Property | Debug value |
|---|---|
| `applicationIdSuffix` | `.debug` |
| `debuggable` | `true` |
| `minifyEnabled` | `false` |
| `API_BASE_URL` | `http://10.0.2.2:8000/api/v1` (emulator) or `http://<local-ip>:8000/api/v1` (device) |
| Signing | Debug keystore (auto-generated by Android Studio) |

The IP `10.0.2.2` is the Android emulator's alias for the host machine's `localhost`.
When running on a physical device on the same Wi-Fi network, replace with your machine's
LAN IP (e.g. `192.168.1.10`).

### Release (CI / production)

Build command (CI — requires keystore secrets):

```bash
./gradlew bundleRelease   # produces .aab for Google Play
./gradlew assembleRelease # produces .apk for direct distribution
```

Key properties:

| Property | Release value |
|---|---|
| `applicationId` | `com.chitsmart` |
| `debuggable` | `false` |
| `minifyEnabled` | `true` (R8) |
| `shrinkResources` | `true` |
| `API_BASE_URL` | Production API URL (injected via `gradle.properties` or CI secret) |
| Signing | Production keystore (stored as `KEYSTORE_BASE64` GitHub secret) |

Keystore secrets required in GitHub Actions:

```
KEYSTORE_BASE64      base64-encoded .jks file
KEYSTORE_PASSWORD    keystore password
KEY_ALIAS            key alias
KEY_PASSWORD         key password
```

See `android.yml` → `build-release` job for the full signing workflow.

### Build variant matrix

| Variant | Gradle task | Output | Environment |
|---|---|---|---|
| `debugLocalEmulator` | `assembleDebug` | `.apk` | Local emulator |
| `debugLocalDevice` | `assembleDebug` | `.apk` | Physical device on LAN |
| `releaseCI` | `bundleRelease` | `.aab` | CI → Google Play internal |
| `releaseProduction` | `bundleRelease` | `.aab` | Google Play production |

## Admin dashboard (React / Vite)

### Local development (hot reload)

```bash
cd admin
npm install
npm run dev
```

Vite dev server: `http://localhost:5173`  
API proxy: all `/api/*` requests are proxied to `http://localhost:8000` via `vite.config.ts`.

Environment file: `admin/.env.local` (gitignored)

```env
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

### Local Docker (served from container)

The admin app is served as a compiled static build inside Nginx when running the full
Docker Compose stack. See the "Local Docker" section below.

Build inside Docker:

```bash
docker-compose -f docker-compose.yml -f docker-compose.admin.yml up --build admin
```

### Staging build (CI)

```bash
cd admin
VITE_API_BASE_URL=https://api.staging.chitsmart.in/api/v1 npm run build
```

The `VITE_API_BASE_URL` variable is injected at **build time** by Vite. It is baked into
the static bundle — it is not read at runtime. Set it via a GitHub Actions environment
secret named `VITE_API_BASE_URL` on the `staging` environment.

### Production build (CI)

```bash
cd admin
VITE_API_BASE_URL=https://api.chitsmart.in/api/v1 npm run build
```

Output: `admin/dist/` — upload to your static hosting provider (Vercel, Netlify, S3 +
CloudFront, or Nginx on a VM).

### Build variant matrix

| Variant | Command | `VITE_API_BASE_URL` | Hosting |
|---|---|---|---|
| Local dev | `npm run dev` | `http://localhost:8000` | Vite dev server |
| Local Docker | `npm run build` (inside Docker) | `http://api:8000` | Nginx container |
| Staging | `npm run build` (CI) | `https://api.staging.chitsmart.in` | Vercel / Netlify staging |
| Production | `npm run build` (CI) | `https://api.chitsmart.in` | Vercel / Netlify production |

## Backend API (Python / FastAPI)

### Local development (uvicorn with hot reload)

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env     # fill in SECRET_KEY and OPENAI_API_KEY
alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

API: `http://localhost:8000`  
OpenAPI docs: `http://localhost:8000/docs`

Database: PostgreSQL running in Docker (`docker-compose up -d db`).

### Local Docker (full stack)

The backend runs as a container (`chitsmart_api`) with hot-reload via a bind mount.

```bash
docker-compose up --build
```

Container reads `backend/.env` for secrets. The `DATABASE_URL` inside the container uses
the Docker service hostname `db` rather than `localhost`:

```env
DATABASE_URL=postgresql+asyncpg://chitsmart:password@db:5432/chitsmart_dev
```

### Staging / production (Docker image)

The backend is containerised using `backend/Dockerfile`. The CI pipeline (`backend.yml`)
builds and pushes the image to GitHub Container Registry on every push to `main` or
`develop`.

Image tags:

| Branch | Tag |
|---|---|
| `main` | `ghcr.io/<owner>/chitsmart-backend:latest` |
| `main` | `ghcr.io/<owner>/chitsmart-backend:<sha8>` |
| `develop` | `ghcr.io/<owner>/chitsmart-backend:develop` |
| `develop` | `ghcr.io/<owner>/chitsmart-backend:develop-<sha8>` |

Production environment variables (set via your cloud provider's secret manager — never
in the image or repository):

```env
DATABASE_URL=postgresql+asyncpg://user:pass@managed-db-host:5432/chitsmart
SECRET_KEY=<64-char random hex>
OPENAI_API_KEY=sk-...
PAYMENT_KEY_ID=rzp_live_...
PAYMENT_KEY_SECRET=...
SMS_API_KEY=...
DEBUG=false
ALLOWED_ORIGINS=https://admin.chitsmart.in
```

### Build variant matrix

| Variant | How to run | Database | Hot reload |
|---|---|---|---|
| Local dev | `uvicorn --reload` | Docker `db` container | Yes |
| Local Docker | `docker-compose up` | Docker `db` container | Yes (bind mount) |
| CI test | GitHub Actions + Postgres service container | Ephemeral test DB | No |
| Staging | Docker image from GHCR on staging host | Managed PostgreSQL | No |
| Production | Docker image from GHCR on production host | Managed PostgreSQL | No |

## Local Docker — full stack

Running all services together with `docker-compose up` gives you the closest local
approximation of the production topology.

### Services

| Service | Container name | Port | Image |
|---|---|---|---|
| PostgreSQL + pgvector | `chitsmart_db` | `5432` | `pgvector/pgvector:pg16` |
| Backend API | `chitsmart_api` | `8000` | Built from `./backend/Dockerfile` |

The admin dashboard is **not** in `docker-compose.yml` by default because Vite's dev
server with hot reload is faster during development. Add it only when you need to test
the static build in a containerised Nginx.

### Starting the full local stack

```powershell
# Start only the database (recommended for active development)
docker-compose up -d db

# Start database + API (no hot reload for API)
docker-compose up -d

# Start with forced rebuild
docker-compose up --build -d

# View logs
docker-compose logs -f api
docker-compose logs -f db

# Stop all
docker-compose down

# Stop and delete all data (destructive)
docker-compose down -v
```

### Health checks

After `docker-compose up -d`:

```powershell
# Database ready?
docker exec chitsmart_db pg_isready -U chitsmart

# API ready?
Invoke-RestMethod http://localhost:8000/health

# API docs accessible?
Start-Process "http://localhost:8000/docs"
```

### Migrations in Docker

```bash
# Run migrations inside the running api container
docker exec chitsmart_api alembic upgrade head

# Or run from host against the Docker DB
cd backend
$env:DATABASE_URL = "postgresql+asyncpg://chitsmart:password@localhost:5432/chitsmart_dev"
alembic upgrade head
```

### Environment variable precedence in Docker

The `api` service in `docker-compose.yml` loads `backend/.env` via `env_file`, then
overrides `DATABASE_URL` to use the `db` service hostname. Any variable set in the
`environment:` block wins over `env_file`.

```yaml
env_file: ./backend/.env            # loaded first
environment:
  DATABASE_URL: postgresql+asyncpg://chitsmart:password@db:5432/chitsmart_dev  # overrides
```

## Cloud deployment (staging and production)

### Backend deployment

The backend is a stateless Docker container. Recommended hosting options:

| Option | When to use |
|---|---|
| **Railway / Render** | Simple deployments, no Kubernetes needed |
| **Google Cloud Run** | Serverless containers, auto-scaling to zero |
| **AWS ECS Fargate** | Full AWS ecosystem, managed containers |
| **VM + Docker Compose** | Full control, predictable cost, single-server |

Minimum resource requirements (production estimate):

| Resource | Minimum | Recommended |
|---|---|---|
| CPU | 0.5 vCPU | 1 vCPU |
| Memory | 512 MB | 1 GB |
| Database | PostgreSQL 16 with pgvector extension | Managed (AWS RDS, Cloud SQL, Supabase) |

Database: pgvector extension is required for the RAG pipeline. Verify your managed
PostgreSQL provider supports it before provisioning.

### Admin dashboard deployment

The compiled `admin/dist/` output is a static site. Recommended hosting:

| Option | When to use |
|---|---|
| **Vercel** | Zero-config, automatic preview deployments per PR |
| **Netlify** | Similar to Vercel, good free tier |
| **AWS S3 + CloudFront** | Full AWS ecosystem, custom domain, WAF |
| **Nginx on the same VM as the backend** | Simplest single-server setup |

The `admin.yml` workflow has a placeholder deploy step using rsync over SSH. Replace
it with your provider's action (see comments in `admin.yml`).

### Android distribution

| Channel | When |
|---|---|
| Google Play internal track | Every `main` push (via CI) |
| Google Play closed testing | Pre-release QA |
| Google Play production | After sign-off |
| Firebase App Distribution | For internal testers who are not on Play |

The `android.yml` `build-release` job produces a signed `.aab`. Uncomment the
`r0adkll/upload-google-play` action in `android.yml` to automate Play Store upload.

### Required GitHub Actions secrets by environment

Set these under **Repository settings → Secrets and variables → Actions**:

#### Repository-level secrets (all environments)

| Secret | Description |
|---|---|
| `KEYSTORE_BASE64` | Base64 of the Android signing keystore |
| `KEYSTORE_PASSWORD` | Keystore password |
| `KEY_ALIAS` | Key alias |
| `KEY_PASSWORD` | Key password |

#### Environment secrets — `staging`

| Secret | Description |
|---|---|
| `VITE_API_BASE_URL` | `https://api.staging.chitsmart.in/api/v1` |
| `DEPLOY_HOST` | Staging server hostname |
| `DEPLOY_USER` | SSH user |
| `DEPLOY_PATH` | Remote path for admin dist |
| `SSH_PRIVATE_KEY` | SSH private key for deployment |

#### Environment secrets — `production`

| Secret | Description |
|---|---|
| `VITE_API_BASE_URL` | `https://api.chitsmart.in/api/v1` |
| `DEPLOY_HOST` | Production server hostname |
| `DEPLOY_USER` | SSH user |
| `DEPLOY_PATH` | Remote path |
| `SSH_PRIVATE_KEY` | SSH private key |

## Build troubleshooting

### "pgvector extension not found"

The `docker-compose.yml` uses `pgvector/pgvector:pg16` which includes the extension.
If using a plain `postgres:16` image, install it manually:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### "Cannot connect to api:8000 from admin container"

When both are in Docker Compose, the API hostname is `api` (the service name), not
`localhost`. Set:

```env
VITE_API_BASE_URL=http://api:8000/api/v1
```

### "Alembic target database is not up to date"

```bash
alembic current         # shows current revision
alembic upgrade head    # applies pending migrations
```

### Android "API_BASE_URL not found in BuildConfig"

Ensure `build.gradle` reads the property and injects it:

```kotlin
android {
    defaultConfig {
        buildConfigField("String", "API_BASE_URL",
            "\"${project.findProperty("API_BASE_URL") ?: "http://10.0.2.2:8000/api/v1"}\"")
    }
}
```
